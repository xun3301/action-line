# StoryShell —— 终端文字交互游戏引擎

一款在终端运行的文字类交互游戏：**玩家**自由输入动作或对白，**模型**（OpenAI 兼容 API）
依据**剧本**推进剧情、维护状态、判定章节与结局，**引擎**是最终裁判。

- 剧本是即插即用的 Markdown + YAML frontmatter 文件，丢进 `scripts/` 即可游玩。
- 引擎校验所有状态、章节、结局；模型只「建议」，不能越权。
- 分段式披露控制上下文容量，长期会话 token 有界。

## 快速开始

```bash
# 1. 安装依赖（Python 3.10+；推荐 3.11+）
pip install -r requirements.txt

# 2. 创建配置（复制模板并填入 api_key）
cp config.example.toml config.toml

# 3. 运行
python main.py
```

`base_url` 兼容 DeepSeek / 通义 / 豆包 / Ollama 等一切 OpenAI 兼容端点。

选择剧本后展示开场白，进入回合循环。直接输入文字即可行动或对话。

## 斜杠命令

| 命令 | 作用 |
|---|---|
| `/save [名字]` | 存档（默认时间戳名；给名字则写入文件名、同名覆盖），同时写 `.bak` |
| `/load` | 列出该剧本所有槽位供选择 |
| `/status` | 查看当前状态变量、章节、结局条件满足度 |
| `/end` | 结局命中且剧本开启 `confirm_ending` 时，确认结束 |
| `/quit` | 退出 |

存档位于 `saves/<剧本名>/<文件名>.json`（默认文件名为时间戳），每剧本上限 `max_saves`（默认 20），超出滚动删除最旧。

## 目录结构

```
storyshell/
├── main.py                 # 入口：剧本选择菜单 → 回合循环
├── config.toml             # API 与游戏配置（含密钥，不入库）
├── config.example.toml     # 配置模板（无密钥，入库）
├── requirements.txt
├── engine/
│   ├── script.py           # 剧本解析 + 加载期校验
│   ├── condition.py        # 条件表达式解析与求值
│   ├── prompt.py           # 系统 prompt 组装（分段披露 + 摘要 + 原文）
│   ├── state.py            # 游戏状态（变量表、校验、增量应用；FlowState 流程元状态）
│   ├── model.py            # API 调用、重试、JSON 容错解析
│   ├── save.py             # 存档/读档（多槽位 + .bak）
│   └── game.py             # 回合主循环、章节推进、结局结算、斜杠命令
└── scripts/
    ├── template.md         # 带注释的空白剧本骨架
    ├── demo.md             # 完整演示剧本（星海旅馆，3 章 / 4 类变量 / 3 结局）
    └── midnight_radio.md   # 无声电台（4 章含 when 门控 / 6 变量 / 5 结局，含倒计时与误导地点）
```

## 剧本格式

单文件 Markdown + YAML frontmatter，六字段：`title` / `intro` / `constant` /
`chapters` / `variables` / `endings`。正文用 `## 章节: <id>` 分隔章节全文。
详见 `scripts/template.md` 与 `scripts/demo.md`。

变量类型：`bool` / `int` / `str` / `str[]`。条件语法：`== != > >= < <=`、
`contains`、`&&`（不支持 `||` 与括号）。

结局除 `id` / `name` / `when` 外，另支持两个可选字段：
- `auto: true` —— 条件满足即由**引擎自动结算**（无需模型声明），触发即结束；
- `priority: <整数>` —— 自动结局同时满足时的结算优先级（越大越优先，同值时按声明顺序）。

失败/超时/死亡类结局建议设 `auto: true` 并给高 `priority`，让引擎确定性收束。

frontmatter 顶层另支持两个**可选**字段（作者可选、缺省不干预）：
- `max_turns: <正整数>` —— 整局回合上限；达到即软结束（不算结局）。省略 = 不限。
- `confirm_ending: true` —— 命中结局后先挂起，玩家输入 `/end` 确认才正式结束；输入其它内容则取消挂起继续。省略 = false（命中即结束）。

## 引擎能力

- **加载期校验**：未声明变量、缺章节正文等坏剧本启动即报错并指明原因/位置
- **状态增量应用**：只接受剧本声明过的变量，类型不符/未声明的字段丢弃并告警
- **结局结算**：条件满足才结算；`auto` 结局由引擎确定性收束（支持 `priority` 优先级）
- **存档/读档**：多槽位往返一致，含 `.bak` 备份；读档校验 schema 版本与剧本一致性
- **JSON 容错**：代码围栏剥离、尾逗号/缺引号修复、裸文本降级
- **上下文有界**：prompt 组装按预算先丢旧原文、再丢旧摘要，长期会话 token 有界
- **流程元状态**：FlowState（当前章节/回合数/结局状态）与玩家数据 GameState 分离，随存档持久化
- **路由可观测**：章节/结局拒绝时指明「哪条子句未满足 + 当前实际值」，便于剧本作者调试
- **失败降级**：超时 / 内容过滤 / 永久错误 / 格式错误分别给出不同提示与 fallback，游戏不中断

## 失败恢复（原则：退化而不是崩溃）

- 网络/限流/5xx：指数退避重试 3 次；仍失败则提示玩家并保留输入，回车重试。认证/参数错误（401/400 等）立即报错，不重试。
- **超时**：识别为瞬时错误，指数退避重试；仍失败提示「模型响应超时」，保留输入重试。
- **内容过滤**：识别为永久错误，不重试；提示「模型因安全策略拒绝生成」。
- 非法 JSON：重试 1 次（附「上次输出需为合法 JSON」提示）；再失败则 narrative 裸输出并提示「未解析为 JSON，状态未更新」，游戏不中断。
- 存档损坏：报错并列出该剧本目录下 `.bak` 备份。
- 状态更新非法：丢弃非法字段 + 告警，游戏继续。
